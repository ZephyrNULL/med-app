Building the Care Cube Circuit in Cirkit Designer (ESP32-S3 Simulator)
Full-replica build + live temperature/humidity streaming to the Care Cube mobile app
Platform: Cirkit Designer — app.cirkitdesigner.com
Target board: ESP32-S3 (simulated)
Companion code: cirkit/sketch.ino
Repo: care_cube
Estimated build time: 15–25 minutes

1. Overview

This guide builds a complete, simulated copy of the Care Cube medicine box inside Cirkit Designer and connects it to the same MQTT broker the Care Cube mobile app uses, so real sensor values appear on your phone.

What you will have when finished

  • An ESP32-S3 running the Care Cube firmware (simulated).
  • DHT22 temperature/humidity readings published every 30 seconds to HiveMQ Cloud topic carecube/carecube-001/status.
  • Dose reminders at 08:00, 10:00, 12:00, 14:00, 16:00 and 20:00 that turn on an LED + buzzer and publish events on carecube/carecube-001/event.
  • Schedule changes pushed from the app arriving on carecube/carecube-001/schedule/set.
  • The temperature and humidity cards on the phone app updating live.

Prerequisites

  • A desktop browser (Chrome or Edge recommended) with internet access.
  • A free Cirkit Designer account (Sign In at app.cirkitdesigner.com).
  • The firmware file cirkit/sketch.ino from the repository (Chapter 8 of this guide).
  • (Optional but recommended) the Care Cube app installed on a phone for the end-to-end verification in Chapter 10.
Important: Cirkit Designer does not support importing a circuit from a file. The workspace is cloud-based and each project lives at app.cirkitdesigner.com/project/<uuid>. You build the circuit once, manually, inside the browser using the steps below.

2. Create the project

  1. Open https://app.cirkitdesigner.com in your browser.
  2. Make sure you are signed in (top-right corner: Sign in / Sign up).
  3. Click Start a new circuit project (blank project).
  4. A new empty workspace opens. The left panel is the Parts library, the center is the canvas, and the top-right area has the Design / Code / Simulate / Upload tabs.
This simulator supports the ESP32-S3 (Simulation Features table shows the S3 — not the plain ESP32). Every next step in this guide assumes the ESP32-S3 dev board.

Wiring as a picture

Everything shares three groups of nets. Mentally split the build into these three groups and the whole circuit becomes simple:

          GROUP A: POWER (3V3 + GND)
          ┌──────────────┐
          │   3V3 net    │──── DHT22 VCC, LCD VCC, DS1307 VCC, VL53L0X #1..#7 VIN
          │   GND net    │──── DHT22 GND, LCD GND, DS1307 GND, buzzer(-),
          │              │     LED #1..#7 cathode, VL53L0X #1..#7 GND
          └──────────────┘

          GROUP B: I2C BUS (two wires everywhere)
          GPIO21 ── SDA ──┬── LCD SDA
                          ├── DS1307 SDA
                          └── VL53L0X #1..#7 SDA        (9 devices, all
          GPIO22 ── SCL ──┬── LCD SCL                    share the same
                          ├── DS1307 SCL                  two wires)
                          └── VL53L0X #1..#7 SCL

          GROUP C: OUTPUTS (one wire each from the ESP32-S3)
          GPIO16 ── DHT22 DATA
          GPIO 2 ── Buzzer +
          GPIO 4 ── LED 1 anode ... GPIO 15 ── LED 7 anode
          GPIO25 ── VL53L0X #1 XSHUT ... GPIO5 ── VL53L0X #7 XSHUT
Why seven VL53L0X sensors share two wires? All distance sensors are I2C devices that start with the same address (0x29). The firmware uses the XSHUT pin to wake them one at a time, giving each its own address (0x30–0x36) during startup. That is why every sensor gets its own XSHUT wire while SDA/SCL are shared. In simulation the sensors are optional; if one reports "NOT FOUND" the firmware simply skips it.

5. Recommended build order

Building in this order avoids re-touching parts and makes mistakes easy to spot:

  1. Place all 22 parts on the canvas and spread them out.
  2. Wire the power rails first (3V3 and GND) to every part that needs power.
  3. Wire the I2C bus (SDA to GPIO21, SCL to GPIO22) for the LCD, RTC and all sensors.
  4. Wire the single-pin outputs: DHT22 data, buzzer, the seven LEDs.
  5. Wire each VL53L0X XSHUT to its dedicated GPIO.

7. Wiring checklist

Tick each box as you complete it. This is the fastest way to catch a missed wire before you ever run the simulation.

Power

  • 3V3 → DHT22 VCC
  • 3V3 → LCD VCC
  • 3V3 → DS1307 VCC
  • 3V3 → VL53L0X #1–#7 VIN (7 wires)
  • GND → DHT22 GND
  • GND → LCD GND
  • GND → DS1307 GND
  • GND → Buzzer –
  • GND → LED #1–#7 cathode (7 wires)
  • GND → VL53L0X #1–#7 GND (7 wires)

I2C bus

  • GPIO21 → LCD SDA
  • GPIO22 → LCD SCL
  • GPIO21 → DS1307 SDA
  • GPIO22 → DS1307 SCL
  • GPIO21 → VL53L0X #1–#7 SDA (7 wires)
  • GPIO22 → VL53L0X #1–#7 SCL (7 wires)

Signals

  • GPIO16 → DHT22 DATA
  • GPIO2 → Buzzer +
  • GPIO4/12/19/18/23/13/15 → LED #1–#7 anode
  • GPIO25/26/27/32/33/14/5 → VL53L0X #1–#7 XSHUT

Do a final visual review

  • Any wire that should hit GND but doesn't will usually be the difference between "works" and "nothing happens" — double-check the black wires.
  • Confirm no SDA wire accidentally touches SCL (crossed wires are the #1 wiring error in this build).
  • Confirm each LED's anode/cathode orientation; an inverted LED stays dark.

8. Load the code

  1. In the Cirkit workspace click the Code tab (top-right area). It opens an Arduino sketch editor already targeted at the ESP32-S3.
  2. Delete the default sketch.
  3. Open cirkit/sketch.ino from this repository and paste all of it into the Code tab.
  4. Save (the project auto-saves to the cloud).

The sketch already handles the simulator specifics:

  • Connects to the virtual WiFi network CirkitWifi (no password).
  • Uses WiFiClientSecure + setInsecure() to talk TLS to the HiveMQ Cloud broker on port 8883.
  • Publishes to carecube/carecube-001/status every 30 seconds.
  • Subscribes to schedule changes and alarm-stop commands.
  • Initializes every VL53L0X gracefully (missing ones are skipped, never a crash loop) and falls back to the simulation clock if the DS1307 is missing.
The MQTT client id in the sketch is carecube-001-cirkit. Only one client may use that id on the broker at a time. If your Wokwi demo is also running, stop it (or change the id suffix) or you will see connection churn. See Chapter 11.

Interactive parts

  • Drag the DHT22 value in the simulator (temperature/humidity slider). Within ~30 seconds the new values appear in the console and on the LCD.
  • At each dose time the matching LED lights and the buzzer sounds; the console prints REMINDER -> SENSOR n TAKE MEDICINE.

10. Verify end-to-end with the Care Cube app

  1. Build and install the app on your phone (the usual flutter build apk --debug + adb workflow), leaving the Cirkit simulation running in the browser.
  2. Open the app and sign in.
  3. Go to the Home tab.
  4. The connection status card should change to "connected".
  5. The Temperature and Humidity cards update every ~30 seconds, and immediately when you move the DHT22 slider in Cirkit.
  6. Change a dose time in the Medicine tab and save — the app publishes carecube/carecube-001/schedule/set and Cirkit's serial console prints Schedule updated via MQTT with the new time.

11. Troubleshooting

SymptomCheck
WiFi never connectsMake sure the sketch connects to CirkitWifi exactly (not Wokwi-GUEST). The simulator only supports this open access point.
MQTT fails with failed, rc=...HiveMQ Cloud needs TLS on port 8883; the sketch already calls setInsecure(). Verify the broker host, username and password in the sketch match lib/config/app_config.dart in the app. As a connectivity sanity check, open Cirkit's official "MQTT Temperature Monitor" example first — if that also fails, the issue is general internet/TLS from the simulator.
Messages arrive, then stopAnother client is using the same MQTT client id on the broker (e.g. the Wokwi demo). Stop the other simulation, or append a different suffix to MQTT_CLIENT_ID in the sketch.
VL53L0X prints NOT FOUND - skippingNormal in the simulator. Temperature/humidity streaming and schedule updates still work. Distance sensing is only used to detect "medicine taken" and emergency doses.
RTC prints NOT FOUNDThe sketch falls back to the simulation clock, so dose timers still fire on time.
App shows "disconnected"App and firmware must use the same broker, device id (carecube-001) and topics. Confirm on the Home tab that the connection card goes green, and that the Cirkit console shows MQTT:Y in the status line.
LEDs stay dark at a dose timeConfirm dose is enabled (all 6 slots default ON) and check the LED's anode/cathode wiring. The simulator runs faster than wall-clock; wait for the next scheduled minute to elapse.
Nothing appears on the LCDCheck I2C wiring (SDA → GPIO21, SCL → GPIO22) and that the LCD part is the I2C variant. If RTC is also missing, firmware still runs but you lose the display.

Appendix B — What the firmware does

Quick map of the state machine so simulation behavior makes sense:

StateBehaviorPublished event
MAIN_SCREENShows time, date, temp/humidity and next dose on the LCD every 0.5 s.—
MEDICINE_REMINDER (dose hour/minute reached)LED of that bay lights, buzzer sounds. If the bay's distance sensor reads > 90 mm for 3 consecutive readings, the dose is logged as taken. reminder_started, then taken
MEDICINE_TAKENConfirmation screen shown for 30 s, LED stays on.—
EMERGENCY_TAKEN (sensor #7 edge detected) Buzzer + LED 7 for 60 s.emergency_taken

"caregiver_stopped" is published when the app sends the remote alarm-stop command on carecube/carecube-001/alarm/stop.

MQTT topic map

App -> Firmware   carecube/carecube-001/schedule/set     (JSON array, 6 slots)
App -> Firmware   carecube/carecube-001/alarm/stop       (caregiver only)
Firmware -> App   carecube/carecube-001/status           {device_id,temperature,humidity,timestamp}
Firmware -> App   carecube/carecube-001/event            {device_id,type,sensor_number,timestamp}
